## Quick-Reference: What NOT to Re-derive

- Identity comes only from the verified chat token → `Principal`. Never from body, query, headers or model output.
- Roles in the token: `tenant`, `pm_member`, `org_admin`, `fbc_operator`. Cross-tenant and cross-user lookups return 404, not 403.
- Never registered as tools, under any role or flag: gate unlock, refund, fee waiver, lease change, payment, notices.
- Writes happen only after a confirmed `confirmations` row, consumed by one atomic `UPDATE … WHERE status='pending' RETURNING`.
- Emergency rules run before any model call and depend on nothing but staff-alert delivery.
- Caps in code: 6 tool calls, 2 retrievals, 400 output tokens, 45 s, 1 retry per provider call.
- Cache breakpoint: nothing per-request before it.
- Mock LLMs at `LLMProvider` (`providers/fake.py`), never at the HTTP layer.
- 3-provider gateway: `anthropic` (`claude-haiku-5-5` / `claude-sonnet-5-5`) ▸ `openai` (`gpt-6-luna` / `gpt-6.1-sol`) ▸ `gemini` (`gemini-3.8-flash` / `gemini-4-argon`).
- SDK facts: `from mcp.server.mcpserver import MCPServer`; no `temperature`/`top_p`/`top_k` on `anthropic` 1.x; `google-genai >=2,<3`; psycopg 3 only; Procrastinate not ARQ; FastAPI pinned `~=0.162.0`.
- Prices and model IDs live only in `config/models.yaml` with a `priced_on` date.
- Quality floors (recall@5, tool-choice, triage) are set in Phases 3, 4, 9 and can only be raised.
- A phase is done only when tests, `ruff`, `mypy --strict` and the migration up/down check are green and this file is updated.
